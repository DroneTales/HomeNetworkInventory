1. О приложении

Home Network Inventory — веб-приложение для учёта устройств домашней сети. Оно хранит информацию об устройствах, их сетевых интерфейсах, IP-адресах, Wi-Fi-сетях, портах, логинах и связях между устройствами.

Приложение поддерживает несколько домов (квартира, загородный дом, офис — любое количество). Каждый дом имеет свой изолированный инвентарь: устройства, подсети, комнаты и связи не пересекаются между домами.

Все изменения сохраняются в базе данных на Raspberry Pi. Доступ — только после входа.

2. Первый вход

Открой адрес приложения, введи Username и Password и нажми Sign in.

При первом входе или после сброса пароля администратором приложение принудительно попросит сменить пароль. Заполни три поля — текущий, новый, подтверждение — и нажми Save.

Выход — кнопка Logout в правом верхнем углу. Сессия автоматически истекает после длительного бездействия.

3. Дома

Приложение поддерживает работу с несколькими домами. У каждого дома — свой набор устройств, локаций, сетей и связей.

3.1. Выбор дома после входа

После входа, если доступно несколько домов, показывается страница Choose a home с карточками домов. На каждой карточке — название, адрес и кнопка Enter для входа.

Если у пользователя доступен ровно один дом, приложение автоматически переходит в него, минуя страницу выбора.

3.2. Работа в выбранном доме

Выбранный дом отображается в шапке рядом с именем пользователя. Все действия (просмотр, создание, редактирование) происходят в контексте этого дома.

Чтобы вернуться к списку домов и выбрать другой — нажми Switch home в шапке.

3.3. Создание и редактирование домов

Создавать, редактировать и удалять дома может только администратор. На странице Choose a home для админа доступна кнопка Add home, а на карточках — кнопки Edit и Delete.

При создании дома задаются:

  • Name — название (обязательно, уникальное).
  • Address — адрес или местоположение (опционально).
  • Photo — фотография дома (JPEG или PNG, до 2 МБ). Показывается на карточке.
  • Active — галка, дом доступен для выбора.

Удалить дом можно только если он пуст — в нём нет устройств, локаций и сетей. Сначала перенеси или удали всё содержимое.

3.4. Назначение пользователей на дома

Обычные пользователи видят только назначенные им дома. Если пользователь не назначен ни на один дом, он не увидит никаких устройств — только сообщение о необходимости обратиться к администратору.

Назначение делается в форме редактирования пользователя (Users → Edit):

  • В блоке Homes показан список назначенных домов с кнопкой Remove.
  • Ниже — выпадающий список неназначенных домов и кнопка Assign, чтобы добавить дом.
  • Администратору дома назначать не нужно — он всегда видит все.

4. Навигация

В верхней панели — разделы:

  • Devices — устройства текущего дома (главный раздел).
  • Connections — связи между устройствами текущего дома.
  • Topology — визуальный граф текущего дома (открывается со страницы Connections).
  • Reference — справочники. Только для пользователей с правом редактирования.
  • Users — управление пользователями приложения. Только для admin.
  • Profile — свой профиль: язык, тема, смена пароля.
  • Help — эта справка.

Разделы Devices, Connections и Reference появляются в шапке только когда дом выбран. Справа — бейдж выбранного дома, кнопка Switch home, имя пользователя и Logout.

На мобильном меню сворачивается в «гамбургер».

5. Устройства

5.1. Список устройств

Показывает все устройства текущего дома в виде таблицы (на десктопе) или карточек (на телефоне). Колонки: Hostname, Name, Type, Vendor, Model, Location, IP Addresses, Gateway, MAC, Actions. Клик по заголовку колонки сортирует список; повторный — меняет порядок на обратный.

Неактивные устройства показываются серым с бейджем inactive.

Бейджи состояния. Под hostname, на второй строке, показываются маленькие цветные бейджи — краткая сводка по устройству (при наведении — подсказка):

  • — устройство является DHCP-сервером.
  • с числом — количество физических портов (показывается, если их больше одного).
  • — у устройства есть исходящие пробросы портов.
  • — у устройства есть входящие пробросы портов.
  • с числом — количество сервисов на устройстве.

Если бейджей нет, под hostname остаётся пустая строка такой же высоты — чтобы строки таблицы оставались выровненными.

IP-адреса. Все адреса устройства перечислены построчно. Справа от каждого адреса — короткая метка типа:

  • LSTAT — локальный статический адрес (серый).
  • LDHCP — локальный DHCP-адрес, пока неизвестен (синий).
  • LRESV — локальный адрес, закреплённый на DHCP-сервере за MAC (фиолетовый).
  • EDHCP — внешний (от провайдера) адрес, выданный динамически, пока неизвестен (бирюзовый).
  • ESTAT — внешний (от провайдера) статический адрес (зелёный).

5.2. Создание устройства

Кнопка Add device в правом верхнем углу. Форма разбита на цветные блоки.

Basic (серый):

  • Hostname — обязательно. Без пробелов, уникально в пределах дома.
  • Human readable name — короткое понятное имя.
  • Device type — тип из справочника. Тип может быть активным (должен иметь IP) или пассивным (хаб, неуправляемый свитч).
  • Vendor и Model — производитель и модель. После выбора вендора список моделей обновляется автоматически.
  • Location — где физически находится в текущем доме.
  • Active — галка, если устройство работает.

Interfaces (синий):

Сетевые интерфейсы устройства, сгруппированные по логической сети, к которой они относятся. Каждая сеть текущего дома — отдельная группа, плюс группа No network («Без сети») для интерфейсов, не привязанных ни к одной сети. Кнопка + Add interface внутри группы добавляет интерфейс сразу в эту сеть. Принадлежность к сети — свойство интерфейса, а не устройства: у роутера с LAN, WAN и гостевым Wi-Fi интерфейсы окажутся сразу в нескольких сетях. У пассивного устройства (хаб, неуправляемый свитч) интерфейсов с сетью нет вовсе. Заголовок группы — ссылка на страницу сети в справочнике.

Поля строки:

  • Name — eth0, wan0, wlan0. Обязательно.
  • Type — один из:
    • ethernet — проводной интерфейс.
    • wifi — клиентский Wi-Fi интерфейс (устройство подключается к существующей сети).
    • wifi_ap — радио точки доступа (устройство раздаёт Wi-Fi сети).
    • wan — аплинк-интерфейс.
    • virtual — виртуальный интерфейс (VLAN, туннель, мост).
    • port — «тупой» разъём без IP (для пассивных устройств).
  • MAC (для wifi_ap — MAC радио) — MAC-адрес. Может быть пустым для static, обязателен для dhcp и reserved. Для Wi-Fi AP это BSSID радио, общий для всех SSID на этом радио.
  • Band — только для wifi_ap. Обязателен. Один из 2.4, 5, 6. Wi-Fi сети, вещаемые через этот интерфейс, наследуют band.
  • IP address — адрес. Для типа port не заполняется.
  • Mask — маска подсети. Для external можно оставить пустой.
  • Type (тип адреса):
    • static — прописан вручную на устройстве. MAC не обязателен.
    • dhcp — выдаётся автоматически. MAC обязателен.
    • reserved — закреплён за MAC-адресом. MAC обязателен.
    • external — внешний IP от провайдера. MAC, маска, шлюз не обязательны.
  • Gateway — шлюз. Если заполнен, должен быть в той же подсети, что и IP (кроме external).
  • DNS — сервер имён. Обычно совпадает со шлюзом.
  • Connected Wi-Fi network — только для интерфейса типа wifi. Обязательно. Выбор сети, к которой подключено устройство.

Интерфейсов может быть несколько — например, LAN и WAN у роутера, или два Wi-Fi радио (2.4 и 5 ГГц) у точки доступа. Поскольку сеть — свойство интерфейса, устройство принадлежит стольким сетям, сколько его интерфейсов привязано к сетям.

Интерфейсы типа port не могут принадлежать сети: селект сети для них не применяется, и они всегда попадают в группу No network.

Уникальность IP. Адрес уникален в пределах дома, но может повторяться на разных интерфейсах одного устройства. Это соответствует реальным роутерам, у которых один управляющий IP используется на eth0, wlan0 и так далее.

Ports (голубой):

Доступно только при редактировании существующего устройства. Физические порты (разъёмы) на корпусе. Используются для связей.

  • Name — WAN, LAN1, LAN2. Обязательно, уникально в пределах устройства.
  • Interface — на какой интерфейс работает порт. Обязательно.
  • Description — короткое описание.

Порт не появится, если у устройства ещё нет ни одного интерфейса. Сначала сохрани устройство с интерфейсами, потом открой редактирование и добавь порты.

Wi-Fi networks (фиолетовый):

Сети, которые раздаёт это устройство (роутер, точка доступа).

  • SSID — имя сети. Обязательно.
  • Broadcast by (вещает через) — какой wifi_ap интерфейс раздаёт этот SSID. Обязательно. Band берётся из интерфейса, поэтому 5 ГГц SSID можно вещать только через 5 ГГц радио.
  • Encryption — тип шифрования.
  • Password — пароль. Хранится в открытом виде.
  • Guest — это гостевая сеть.

Одна точка доступа может раздавать несколько сетей — как через одно радио (multi-SSID), так и через несколько радио (двухдиапазонная точка).

Band берётся из радио, а не из SSID. Чтобы добавить второй диапазон, добавь второй интерфейс wifi_ap с нужным band, затем создай SSID заново и укажи в Broadcast by этот интерфейс.

Интерфейс wifi_ap нельзя удалить, пока через него вещают Wi-Fi сети. Сначала переназначь эти сети на другой интерфейс — или удали их. Форма устройства предупредит об этом до удаления.

DHCP pools (оранжевый):

Пулы адресов, которые выдаёт это устройство (модем, роутер).

  • Name — имя пула.
  • Type — dynamic или fixed.
  • Start IP, End IP — диапазон.
  • Gateway, DNS — параметры для клиентов.
  • Description — описание.

Если новый static IP устройства попадёт в диапазон пула — появится жёлтый баннер после сохранения. Это предупреждение, а не ошибка.

Credentials (красный):

Логины и пароли устройства.

  • Type — admin, ssh, wifi, camera, matter, other.
  • Username, Password — учётные данные.
  • Description — зачем нужен.

Можно добавить несколько записей. Пароли показываются как •••••••• с кнопкой show — но только если у тебя есть право can_view_passwords.

Services (зелёный):

Сервисы, работающие на устройстве (веб-интерфейсы, RTSP-потоки, HomeBridge и т.п.).

  • Name, Protocol (dhcp, dns, ftp, http, https, imap, mqtt, nfs, ntp, other, pop3, rdp, rtp, rtsp, sftp, smb, smtp, ssh, telnet, vnc).
  • URL — полный адрес. Если начинается с http://, https:// или rtsp:// — станет кликабельным.
  • Description — короткое описание.

Remarks (жёлтый): свободный текст для всего, что не поместилось.

5.2.1. Пример: Wi-Fi-репитер

Wi-Fi-репитер — это одно устройство, которое одновременно является и Wi-Fi-клиентом, и точкой доступа. Он подключается к основному роутеру по Wi-Fi и перераздаёт сеть под тем же или другим SSID. В инвентаре это моделируется как одно устройство с двумя Wi-Fi-интерфейсами:

  • wlan_client, тип wifi, привязан к Wi-Fi-сети, к которой он подключён (SSID основного роутера). Это его аплинк. Его сеть — та, с которой он ассоциирован, обычно основная LAN.
  • wlan_ap, тип wifi_ap, с band (например 2.4). Это радио, которое раздаёт ретранслируемую сеть. Его сеть — та подсеть, из которой он выдаёт адреса клиентам; обычно та же, что и у аплинка, но может быть и другой (например, отдельная подсеть репитера).

Оба интерфейса живут в одной физической коробке, поэтому устройство состоит сразу в двух логических сетях — это ровно тот случай, ради которого сеть была сделана свойством интерфейса. Добавь ретранслируемую сеть в блоке Wi-Fi networks (фиолетовый), указав в Broadcast by интерфейс wlan_ap; клиенты, которые к ней подключатся, появятся на странице устройства как Wi-Fi-клиенты.

Если репитер вообще не раздаёт Wi-Fi (так называемый проводной репитер), убери интерфейс wlan_ap и добавь вместо него ethernet — сеть является свойством интерфейса, поэтому одно и то же устройство может играть любую роль в зависимости от того, какие интерфейсы у него есть.

5.3. Карточка устройства

Клик по hostname в списке открывает карточку. Все данные — в цветных блоках. Кнопки сверху: Back, Edit, Delete (только admin).

5.4. Редактирование

Та же форма, что при создании, но с заполненными полями. Если удалить интерфейс, к которому привязаны порты и связи — они удалятся автоматически. Изменения применяются только после нажатия Save.

5.5. Удаление

Удаление устройства удаляет всё, что с ним связано: интерфейсы, IP, Wi-Fi, DHCP-пулы, credentials, services, порты, связи. Отменить нельзя.

6. Связи

Раздел показывает все физические и логические связи между портами устройств текущего дома.

6.1. Создание связи

Кнопка Add connection. Сначала выбери устройство, потом порт этого устройства — в Source и в Target. В выпадающих списках только устройства и порты текущего дома.

Дополнительные поля: Type (physical или logical), Cable (цвет или тип), Description, Active.

6.2. Редактирование связи

Нажми иконку карандаша в колонке Actions (на десктопе) или кнопку Edit на мобильной карточке. Используется та же форма, что и при создании, но заполненная текущими значениями. Правила уникальности (см. ниже) действуют и при редактировании — редактируемая связь исключается из проверки.

6.3. Ограничения

  • Source и Target не могут быть одним и тем же портом.
  • Связь A→B и B→A — одна и та же физическая связь. Дубликаты запрещены.
  • Один физический порт может участвовать только в одной связи.
  • Оба порта должны быть из устройств одного дома. Межсайтовые связи не допускаются.
  • Двойной клик по Delete безопасен — второй запрос тихо проигнорируется.

6.4. Wi-Fi-сети

Под основной таблицей — блок Wi-Fi networks со списком всех беспроводных сетей текущего дома и подключённых клиентов. Для каждой сети:

  • В заголовке — SSID, диапазон (2.4/5/6 ГГц), бейдж guest при необходимости и число клиентов.
  • Справа в заголовке — ссылка на устройство-вещатель (роутер или точка доступа).
  • В теле карточки — список клиентских устройств, подключённых к сети.

Сеть показывается только если у неё есть хотя бы один подключённый клиент.

6.5. Устройства по локациям — drag & drop

Внизу страницы — блок Devices by location, группирующий все устройства текущего дома по справочнику Location. Устройства без локации попадают в группу Undefined, она показывается последней.

Пользователи с правом редактирования могут перетаскивать устройства между локациями:

  • Наведи курсор на иконку типа устройства — курсор сменится на «ладонь».
  • Перетащи иконку на карточку другой локации.
  • Карточка-цель подсвечивается пунктирной рамкой, пока ты над ней.
  • Отпусти — устройство перемещается, а location_id обновляется в базе сразу, без перезагрузки страницы.
  • Отпустить на группу Undefined — очистить локацию устройства.
  • Всплывающее уведомление подтверждает успех или сообщает об ошибке.

Перенос между домами невозможен — устройство можно перетащить только в локацию своего дома.

6.6. Связи в карточке устройства

Блок Connections в карточке показывает:

  • outgoing — связи, где это устройство источник.
  • incoming — связи, где это устройство назначение.

7. Топология

Страница Topology показывает визуальную карту текущего дома. Открывается кнопкой Map на странице Connections.

7.1. Что отображается

  • Устройства сгруппированы в контейнеры: Home → Locations → Devices.
  • Устройства без локации обведены оранжевой рамкой и находятся вне блоков локаций.
  • Узел устройства показывает иконку категории и hostname. Цвет иконки зависит от категории (модем, хаб, Wi-Fi-роутер, Wi-Fi-точка доступа, роутер, камера, видеосервер, сервер, прочее).
  • Физические и логические связи между устройствами показаны рёбрами (на уровне устройств, без учёта конкретных портов).
  • Wi-Fi-связи: у вещателя — бейдж Wi-Fi, у клиента — бейдж с SSID.

7.2. Управление

  • Fit — вписать весь граф в окно.
  • Save layout — сохранить текущее расположение узлов для этого дома. Доступно администратору и пользователям с правом редактирования. Позиции хранятся по домам и по устройствам.
  • Reset layout — удалить сохранённые позиции и заново запустить авто-раскладку при следующей загрузке. Запрашивает подтверждение.
  • Back to Connections — вернуться к списку связей.
  • Legend — переключить легенду в углу.
  • Клик по устройству — открыть боковую панель с портами, интерфейсами и IP-адресами.
  • Колесо мыши / жесты — масштаб; перетаскивание фона — панорама.

7.3. Сохранение раскладки

  • Перетащи любой узел, чтобы разложить граф удобным образом, и нажми Save layout. Позиции хранятся по домам и по устройствам; переключение дома или перезагрузка страницы их восстанавливает.
  • Если у узла нет сохранённой позиции (новое устройство или после Reset layout), его размещает авто-раскладка; сохранённые позиции накладываются поверх.
  • Reset layout удаляет сохранённые позиции для текущего дома. При следующей загрузке авто-раскладка запускается с нуля.
  • Позиции устройства удаляются автоматически при удалении устройства из дома.

7.4. Примечания

  • Сам граф строится из данных: рёбра — это связи, контейнеры — локации, бейджи — Wi-Fi-роли. Пользователь задаёт и сохраняет только позиции узлов.
  • Показываются только устройства текущего дома.

8. Проброс портов

Правила проброса портов редактируются прямо в форме устройства, в блоке Port forwarding. Блок доступен только для устройств, тип которых поддерживает проброс (Supports port forwarding в справочнике Device Types).

8.1. Поля

  • External port start, External port end — диапазон портов снаружи.
  • Protocol — tcp, udp или both.
  • Target — либо устройство текущего дома, либо IP вручную (для устройства, которого ещё нет в инвентаре).
  • Internal port start, Internal port end — диапазон портов на внутреннем хосте.
  • Description — короткое описание.
  • Active — отключить вместо удаления, удобно при отладке.

8.2. Ограничения

  • Правило нацелено либо на устройство, либо на IP вручную — не на оба сразу.
  • Целевое устройство должно быть из того же дома, что и роутер.
  • В бейдже в списке устройств учитываются только активные правила.
  • both означает, что правило покрывает TCP и UDP на одном диапазоне портов.

8.3. Входящие пробросы в карточке устройства

Если устройство является целью правил проброса другого устройства, эти правила показываются в отдельном блоке на его странице — так видно, какие порты и откуда открыты.

9. Справочники

Раздел Reference — список справочников. Доступен пользователям с правом редактирования. Часть справочников привязана к дому, часть — глобальные.

Привязаны к дому (доступны всем с правом Can edit):

  • Locations — комнаты (Зал, Спальня, Кухня, Стойка). У каждого дома свой набор. Одинаковые названия в разных домах разрешены.
  • Networks — подсети дома с адресом, маской, VLAN. У каждого дома свои.

Глобальные, только для администратора (общие для всех домов):

  • Device Types — типы устройств. Active = да — «умное» устройство (должно иметь IP). Active = нет — пассивное (хаб, свитч без управления), не должно иметь IP.
  • Vendors — производители.
  • Models — модели. Привязаны к вендору.
  • Credential Types — типы учётных данных.

Что важно:

  • Удаление невозможно, если на запись ссылаются устройства. Появится красный баннер с объяснением.
  • Названия Locations и Networks уникальны в пределах дома, остальные — глобально.

10. Пользователи

Раздел Users доступен только администратору.

8.1. Роли

  • admin — полный доступ, включая управление пользователями, домами и удаление устройств. Видит все дома.
  • user — обычный пользователь с тремя флагами прав. Видит только назначенные дома.

8.2. Три флага прав (для user)

  • Can edit — создавать, редактировать, удалять устройства и связи.
  • Can view passwords — видеть пароли устройств.
  • Can change passwords — менять пароли существующих устройств.

Запрещённые комбинации:

  • Нельзя дать Can change passwords, если снят Can edit.
  • Нельзя дать Can change passwords, если снят Can view passwords.

8.3. Назначение домов

В форме редактирования пользователя есть блок Homes:

  • Таблица назначенных домов с кнопкой Remove.
  • Выпадающий список неназначенных домов и кнопка Assign, чтобы добавить.
  • Если пользователь не назначен ни на один дом, он не увидит никаких устройств.
  • Для admin блок показывает сообщение о том, что администратор видит все дома.

8.4. Действия

  • Add user — создать пользователя.
  • Edit — изменить имя, роль, права, язык, тему, назначение домов.
  • Reset password — сбросить пароль и (опционально) обязать сменить при следующем входе.
  • Delete — удалить пользователя. Default Admin удалить нельзя.

11. Профиль

Раздел Profile — твоя личная страница.

  • Account — имя, роль, права.
  • Preferences — Language (English/Русский) и Theme (Auto/Light/Dark). Применяются сразу после Save.
  • Change password — смена своего пароля (текущий + новый + подтверждение).

12. Права и роли

Admin видит всё и может всё.

User видит:

  • Только назначенные ему дома.
  • Список устройств и карточки этих домов — всегда.
  • Связи — всегда.
  • Справочники — если есть Can edit.
  • Раздел Users — никогда.

Кнопки Add/Edit/Delete показываются только при праве Can edit. Пароли видны только при Can view passwords. Поле пароля в форме редактирования доступно только при Can change passwords.

13. Полезные советы

  • Сначала дома. Перед созданием устройств заведи дом (если у тебя их несколько). Админ создаёт дома на странице выбора.
  • Потом справочники. Внутри дома заполни локации и сети. Глобальные справочники (типы, вендоры, модели, credential-типы) — один раз для всех домов.
  • Порты — при редактировании. Создай устройство с интерфейсами, сохрани, открой Edit, добавь порты.
  • Тип IP-адреса: static — вручную, dhcp — автоматически, reserved — за MAC, external — от провайдера. В списке устройств рядом с адресом показывается короткая метка: LSTAT, LDHCP, LRESV, EDHCP, ESTAT.
  • Быстрый перенос устройств между локациями. На странице Connections в блоке Devices by location перетащи иконку типа устройства на карточку другой локации — устройство переедет мгновенно. Перетаскивание на Undefined очищает локацию.
  • Топология как проверка. Открой граф, чтобы найти устройства без связей, локации без жильцов или Wi-Fi-клиентов, не привязанных ни к одной сети.
  • Внешний IP модема добавляется как отдельный интерфейс типа wan с типом адреса external. Маска, шлюз, MAC можно не указывать.
  • Wi-Fi: раздача vs подключение. Сети, которые устройство раздаёт — в блоке Wi-Fi networks. Подключение — в интерфейсе типа wifi через поле Connected Wi-Fi network.
  • Предупреждение про DHCP. Если static IP попал в диапазон пула — жёлтый баннер. Это не ошибка, но проверь на конфликт.
  • Уникальность в доме. Hostname, Local IP, имена локаций и сетей уникальны в пределах дома. MAC — глобально.

14. Возможные проблемы

«Safari не может найти страницу». Редко. Это особенность Safari с долгими паузами между открытием формы и сохранением. Нажми Back и сохрани заново — сработает.

«Internal Server Error». Ошибка на стороне сервера. Сообщи администратору.

Не вижу ни одного дома. Обратись к администратору — тебя нужно назначить хотя бы на один дом.

Не могу удалить дом. Удалить можно только пустой дом. Удали или перенеси все устройства, локации и сети из него.

Не могу удалить запись справочника. На неё ссылаются устройства. Сначала убери ссылки.

Забыл пароль. Пароль приложения может сбросить admin через раздел Users. Пароли устройств хранятся в открытом виде в карточке — их видно.

IP-адрес не сохраняется. Проверь: адрес уникален в пределах дома, шлюз в той же подсети (кроме external), MAC заполнен для dhcp и reserved, интерфейс не типа port.

Связь не создаётся. Проверь: Source и Target — разные порты, такая связь ещё не существует, оба порта из устройств одного дома, у обоих устройств есть порты.

15. Горячие клавиши

  • Cmd+Shift+N (Safari) — приватное окно. Помогает, если браузер кэширует старое.
