1. About

Home Network Inventory is a web application for tracking devices on a home network. It stores information about devices, their network interfaces, IP addresses, Wi-Fi networks, ports, credentials, and connections between devices.

The application supports multiple homes (an apartment, a country house, an office — any number). Each home has its own isolated inventory: devices, subnets, rooms, and connections do not cross between homes.

All changes are saved to a database on a Raspberry Pi. Access requires signing in.

2. First sign-in

Open the application URL, enter your Username and Password, and click Sign in.

On the first sign-in, or after an administrator resets your password, the application will force you to change the password. Fill in three fields — current password, new password, confirmation — and click Save.

To sign out, use the Logout button in the top-right corner. The session expires automatically after a period of inactivity.

3. Homes

The application supports multiple homes. Each home has its own set of devices, locations, networks, and connections.

3.1. Choosing a home after sign-in

After signing in, if more than one home is available, the Choose a home page is shown with cards for each home. Each card has a name, an address, and an Enter button.

If a user has access to exactly one home, the application goes straight into it, skipping the selection page.

3.2. Working in the selected home

The selected home is shown in the header next to the username. All actions (viewing, creating, editing) happen in the context of that home.

To go back to the list of homes and pick another one — click Switch home in the header.

3.3. Creating and editing homes

Only an administrator can create, edit, and delete homes. On the Choose a home page, admins see an Add home button and Edit / Delete buttons on each card.

When creating a home you provide:

  • Name — required, unique.
  • Address — optional.
  • Photo — a picture of the home (JPEG or PNG, up to 2 MB). Shown on the card.
  • Active — whether the home is selectable.

A home can be deleted only if it is empty — no devices, locations, or networks inside. Remove or move everything first.

3.4. Assigning users to homes

Regular users see only the homes they are assigned to. If a user is not assigned to any home, they see nothing — just a message suggesting they contact the administrator.

Assignment is done on the user edit page (Users → Edit):

  • The Homes block shows the list of assigned homes with a Remove button.
  • Below is a dropdown of unassigned homes and an Assign button to add one.
  • Admins do not need to be assigned — they always see all homes.

4. Navigation

The top navigation bar has the following sections:

  • Devices — devices in the current home (the main section).
  • Connections — links between devices in the current home.
  • Topology — a visual graph of the current home (opened from the Connections page).
  • Reference — reference data. Only for users with edit rights.
  • Users — application user management. Admin only.
  • Profile — your profile: language, theme, password change.
  • Help — this guide.

The Devices, Connections, and Reference sections appear in the header only when a home is selected. On the right — a badge with the current home, a Switch home button, the username, and Logout.

On mobile, the menu collapses into a hamburger.

5. Devices

5.1. Device list

Shows all devices of the current home as a table (desktop) or cards (mobile). Columns: Hostname, Name, Type, Vendor, Model, Location, IP Addresses, Gateway, MAC, Actions. Click any column header to sort; click again to reverse.

Inactive devices are greyed out with an inactive badge.

Status badges. Under the hostname, on a second line, small coloured badges summarise the device at a glance (hover for a tooltip):

  • — the device is a DHCP server.
  • with a number — number of physical ports (shown when more than one).
  • — the device has outgoing port forwards.
  • — the device has incoming port forwards.
  • with a number — number of services running on the device.

If a device has no badges, an empty line of the same height is reserved so that rows stay aligned.

IP addresses. All addresses of the device are listed, one per line. Each address carries a short type tag on the right:

  • LSTAT — local static address (grey).
  • LDHCP — local DHCP address, not yet known (blue).
  • LRESV — local address reserved on the DHCP server by MAC (purple).
  • EDHCP — external (ISP) address, assigned dynamically, not yet known (teal).
  • ESTAT — external (ISP) static address (green).

5.2. Creating a device

Use the Add device button in the top-right corner. The form is split into colour-coded blocks.

Basic (grey):

  • Hostname — required. No spaces, unique within a home.
  • Human readable name — a short, friendly name.
  • Device type — a type from the reference data. Types can be active (must have an IP) or passive (hub, unmanaged switch).
  • Vendor and Model — manufacturer and model. After choosing a vendor, the model list is refreshed automatically.
  • Location — where the device physically is in this home.
  • Active — tick if the device is operational.

Interfaces (blue):

Network interfaces of the device, grouped by the logical network they belong to. Every network of the current home has its own group, plus a No network group for interfaces that are not bound to any network. Use the + Add interface button inside a group to add an interface directly to that network. Network membership is a property of the interface, not of the device: a router with LAN, WAN, and guest Wi-Fi will have interfaces in several networks at once. A passive device (hub, unmanaged switch) has no interfaces with a network at all. The group header is a link to the network's reference page.

Row fields:

  • Name — eth0, wan0, wlan0. Required.
  • Type — one of:
    • ethernet — wired interface.
    • wifi — Wi-Fi client interface (the device connects to an existing Wi-Fi network).
    • wifi_ap — Wi-Fi Access Point radio (the device broadcasts Wi-Fi networks).
    • wan — uplink interface.
    • virtual — virtual interface (VLAN, tunnel, bridge).
    • port — "dumb" socket with no IP (for passive devices).
  • MAC (or Radio MAC for wifi_ap) — MAC address. Can be empty for static, but is required for dhcp and reserved. For a Wi-Fi AP it is the BSSID of the radio, shared by all SSIDs on that radio.
  • Band — only for wifi_ap. Required. One of 2.4, 5, 6. Wi-Fi networks broadcast through this interface inherit the band.
  • IP address — the address. Leave empty for type port.
  • Mask — subnet mask. Can be empty for external.
  • Type (address type):
    • static — manually configured on the device. MAC optional.
    • dhcp — assigned automatically. MAC required.
    • reserved — bound to a MAC address. MAC required.
    • external — external IP from the ISP. MAC, mask, gateway optional.
  • Gateway — if filled in, must be in the same subnet as the IP (except for external).
  • DNS — name server. Usually the same as the gateway.
  • Connected Wi-Fi network — only for interfaces of type wifi. Required. Choose the network this device is connected to.

A device can have several interfaces — for example, LAN and WAN on a router, or two Wi-Fi AP radios (2.4 GHz and 5 GHz) on an access point. Because the network is a property of the interface, a device belongs to as many networks as it has interfaces bound to networks.

Interfaces of type port cannot belong to a network — the network selector is effectively absent for them, and they always land in the No network group.

IP uniqueness. An address is unique within a home, but may repeat across interfaces of the same device. This matches real routers where the management IP is shared by eth0, wlan0, and so on.

Ports (cyan):

Available only when editing an existing device. Physical ports (sockets) on the device chassis. Used to define connections.

  • Name — WAN, LAN1, LAN2. Required, unique within a device.
  • Interface — which interface this port maps to. Required.
  • Description — short note.

The port field will not appear until the device has at least one interface. Save the device with interfaces first, then open Edit and add ports.

Wi-Fi networks (purple):

Networks this device broadcasts (router, access point).

  • SSID — network name. Required.
  • Broadcast by — which wifi_ap interface broadcasts this SSID. Required. The band is taken from the interface, so a 5 GHz SSID can only be broadcast through a 5 GHz radio.
  • Encryption — encryption type.
  • Password — stored in plain text.
  • Guest — this is a guest network.

An access point can broadcast multiple networks — either through one radio (multi-SSID) or through several radios (dual-band AP).

Band comes from the radio, not the SSID. To add a second band, add a second wifi_ap interface with the desired band, then create the SSID again and set Broadcast by to that interface.

A wifi_ap interface cannot be deleted while any Wi-Fi network is still broadcast through it. Reassign those networks to another interface first — or remove them. The device form warns you before the interface is removed.

DHCP pools (orange):

Address pools this device serves (modem, router).

  • Name — pool name.
  • Type — dynamic or fixed.
  • Start IP, End IP — the range.
  • Gateway, DNS — parameters handed to clients.
  • Description — optional note.

If a new static IP falls within a pool, a yellow banner appears after saving. This is a warning, not an error.

Credentials (red):

Logins and passwords for the device.

  • Type — admin, ssh, wifi, camera, matter, other.
  • Username, Password — credentials.
  • Description — what they are for.

You can add several entries. Passwords are shown as •••••••• with a show button — but only if you have the can_view_passwords permission.

Services (green):

Services running on the device (web UI, RTSP streams, HomeBridge, etc.).

  • Name, Protocol (dhcp, dns, ftp, http, https, imap, mqtt, nfs, ntp, other, pop3, rdp, rtp, rtsp, sftp, smb, smtp, ssh, telnet, vnc).
  • URL — full address. If it starts with http://, https://, or rtsp:// — it becomes clickable.
  • Username and Password — optional per-service credentials. Useful when each service on a device has its own login, separate from the device-level credentials. The password follows the same permission rules as credentials: it is hidden for users without can_view_passwords and read-only for users without can_change_passwords.
  • Description — short note.

Remarks (yellow): free-form text for anything that did not fit elsewhere.

5.2.1. Example: a Wi-Fi repeater

A Wi-Fi repeater is a single device that is both a Wi-Fi client and a Wi-Fi access point at the same time. It connects to your main router over Wi-Fi and rebroadcasts the network under the same or a different SSID. In the inventory this is modelled as one device with two Wi-Fi interfaces:

  • wlan_client, type wifi, bound to the Wi-Fi network it connects to (the main router's SSID). This is its uplink. Its network is the network it is associated with — typically the main LAN.
  • wlan_ap, type wifi_ap, with a band (for example 2.4). This is the radio that broadcasts the repeated network. Its network is the subnet it hands out to clients — usually the same as the uplink, but it can be a different one (for example, a dedicated repeater subnet).

Both interfaces live on the same physical box, so the device is a member of two logical networks at once — this is exactly the case the per-interface network model is designed for. Add the repeated network under Wi-Fi networks (purple) with Broadcast by pointing at wlan_ap, and the clients that associate with it will show up as Wi-Fi clients on the device's page.

If your repeater does not rebroadcast over Wi-Fi at all (a so-called wired extender), drop the wlan_ap interface and add an ethernet interface instead — the network is a property of the interface, so the same device can play either role depending on which interfaces you add.

5.3. Device page

Click a hostname in the list to open the device page. All data is shown in colour-coded blocks. Buttons at the top: Back, Edit, Delete (admin only).

5.4. Editing

The same form as for creation, but pre-filled. If you delete an interface to which ports and connections are tied, they are removed automatically. Changes are applied only after you press Save.

5.5. Deleting

Deleting a device removes everything attached to it: interfaces, IPs, Wi-Fi, DHCP pools, credentials, services, ports, and connections. This cannot be undone.

6. Connections

The section lists all physical and logical connections between device ports of the current home.

6.1. Creating a connection

Click Add connection. First choose a device, then a port of that device — for both Source and Target. Dropdowns show only devices and ports of the current home.

Additional fields: Type (physical or logical), Cable (colour or type), Description, Active.

6.2. Editing a connection

Click the pencil icon in the Actions column (desktop) or the Edit button on the mobile card. The same form is reused, pre-filled with the current values. The uniqueness rules below apply on edit as well — the connection being edited is excluded from the check.

6.3. Rules

  • Source and Target cannot be the same port.
  • A→B and B→A are the same physical connection. Duplicates are not allowed.
  • One physical port can participate in only one connection.
  • Both ports must belong to devices of the same home. Cross-home links are not permitted.
  • Double-clicking Delete is safe — the second request is silently ignored.

6.4. Wi-Fi networks

Below the main table, a Wi-Fi networks block lists all wireless networks of the current home with their connected clients. For each network:

  • The header shows the SSID, the band (2.4/5/6 GHz), a guest badge if applicable, and the number of clients.
  • On the right of the header — a link to the broadcasting device (router or access point).
  • The card body lists the client devices currently connected to the network.

A network is only shown if it has at least one connected client.

6.5. Devices by location — drag & drop

At the bottom of the page, a Devices by location block groups all devices of the current home by their Location reference. Devices without a location go into the Undefined group, shown last.

Users with edit rights can drag a device to another location:

  • Hover over the device type icon — the cursor changes to a grab hand.
  • Drag the icon onto another location card.
  • The target card is highlighted with a dashed outline while you hover over it.
  • Drop — the device is moved and the location_id is updated in the database immediately, without reloading the page.
  • Dropping into the Undefined group clears the device location.
  • A toast confirms success or reports an error.

Cross-home moves are not possible — a device can only be moved to a location of its own home.

6.6. Connections on the device page

The Connections block on the device page shows:

  • outgoing — connections where this device is the source.
  • incoming — connections where this device is the target.

7. Topology

The Topology page shows a visual map of the current home. Open it from the Map button on the Connections page.

7.1. What is shown

  • Devices are grouped into compound containers: Home → Locations → Devices.
  • Devices without a location are outlined in orange and placed outside the location frames.
  • Each device node shows a category icon and the hostname. The icon colour depends on the device category (modem, hub, Wi-Fi router, Wi-Fi access point, router, camera, video server, server, other).
  • Physical and logical connections between devices are drawn as edges (device-level, ignoring individual ports).
  • Wi-Fi relationships: broadcasters get a Wi-Fi badge; clients connected to a Wi-Fi network get a client badge with the SSID.

7.2. Controls

  • Fit — fit the whole graph into the viewport.
  • Save layout — persist the current node positions for this home. Available to administrators and users with edit rights. Positions are stored per home and per device.
  • Reset layout — discard the saved positions and re-run the automatic layout on the next load. Asks for confirmation.
  • Back to Connections — return to the Connections list.
  • Legend — toggle the colour legend in the corner.
  • Click a device — opens the side panel with the device's ports, interfaces, and IP addresses.
  • Mouse wheel / pinch — zoom; drag the background — pan.

7.3. Saving the layout

  • Drag any node to arrange the graph the way you like, then press Save layout. Positions are stored per home and per device; switching homes or reloading the page restores them.
  • If a node has no saved position (a new device, or after Reset layout), the auto-layout places it; saved positions are applied on top of the auto-layout result.
  • Reset layout removes the saved positions for the current home. The next load runs the auto-layout from scratch.
  • Positions of a device are removed automatically when the device is deleted from the home.

7.4. Notes

  • The graph itself is derived from data — edges are connections, containers are locations, badges are Wi-Fi roles. Only node positions are user-defined and persistable.
  • Only devices of the current home are shown.

8. Port forwarding

Port forwarding rules are edited directly inside the device form — in the Port forwarding block. This is only available for devices whose type supports port forwarding (Supports port forwarding in the device type reference).

8.1. Fields

  • External port start, External port end — the port range on the outside.
  • Protocol — tcp, udp, or both.
  • Target — either a device of the current home, or a manual IP (for a device not yet in the inventory).
  • Internal port start, Internal port end — the port range on the internal host.
  • Description — a short note.
  • Active — disable instead of delete when troubleshooting.

8.2. Rules

  • A rule can target either a device or a manual IP, not both.
  • The target device must belong to the same home as the router.
  • Only active rules are counted in the badge on the device list.
  • both means the rule covers TCP and UDP on the same port range.

8.3. Incoming forwards on the device page

If a device is the target of another device's forwarding rules, the incoming rules are shown on the target device page in a separate block — so you can see at a glance which ports are exposed and from where.

9. Reference

The Reference section lists all reference data. Accessible to users with edit rights. Some lists are per home, some are global.

Per home (available to anyone with Can edit):

  • Locations — rooms (Living room, Bedroom, Kitchen, Rack). Each home has its own set. Identical names in different homes are allowed.
  • Networks — subnets of the home with address, mask, VLAN. Each home has its own.

Global — admin only (shared across all homes):

  • Device Types — types of devices. Active = yes — a "smart" device (must have an IP). Active = no — passive (hub, unmanaged switch), must not have an IP.
  • Vendors — manufacturers.
  • Models — hardware models. Belong to a vendor.
  • Credential Types — types of credentials.

Important:

  • Deletion is not possible if devices reference the entry. A red banner explains this.
  • Location and Network names are unique within a home; other lists are global.

10. Users

The Users section is available to the administrator only.

8.1. Roles

  • admin — full access, including user management, home management, and device deletion. Sees all homes.
  • user — regular user with three permission flags. Sees only assigned homes.

8.2. Three permission flags (for role=user)

  • Can edit — create, edit, and delete devices and connections.
  • Can view passwords — see device passwords.
  • Can change passwords — change passwords of existing devices.

Forbidden combinations:

  • Can change passwords cannot be granted without Can edit.
  • Can change passwords cannot be granted without Can view passwords.

8.3. Home assignment

The user edit page has a Homes block:

  • A table of assigned homes with a Remove button.
  • A dropdown of unassigned homes and an Assign button to add one.
  • If a user is not assigned to any home, they see no devices at all.
  • For admin, the block shows a note that admins see all homes.

8.4. Actions

  • Add user — create a user.
  • Edit — change name, role, permissions, language, theme, home assignments.
  • Reset password — reset the password and (optionally) require a change on next sign-in.
  • Delete — remove the user. The default Admin cannot be deleted.

11. Profile

The Profile section is your personal page.

  • Account — name, role, permissions.
  • Preferences — Language (English/Russian) and Theme (Auto/Light/Dark). Applied immediately after Save.
  • Change password — change your own password (current + new + confirmation).

12. Permissions and roles

Admin sees everything and can do everything.

User can see:

  • Only the homes assigned to them.
  • Device list and device pages of those homes — always.
  • Connections — always.
  • Reference — if they have Can edit.
  • Users — never.

Add/Edit/Delete buttons are shown only with the Can edit permission. Passwords are visible only with Can view passwords. The password field in the edit form is available only with Can change passwords.

13. Tips

  • Homes first. Before creating devices, add a home (if you have more than one). Admins create homes on the home selection page.
  • Then reference data. Inside a home, fill in locations and networks. Global reference lists (device types, vendors, models, credential types) are shared across all homes.
  • Ports are added on edit. Create the device with interfaces, save, open Edit, then add ports.
  • IP address type: static — manual, dhcp — automatic, reserved — bound to MAC, external — from the ISP. In the device list each address shows a short tag: LSTAT, LDHCP, LRESV, EDHCP, ESTAT.
  • Move devices between locations quickly. On the Connections page, drag the device type icon in the Devices by location block onto another location card — the device moves instantly. Drop onto Undefined to clear its location.
  • Topology as a sanity check. Open the graph to spot devices with no connections, unassigned locations, or Wi-Fi clients not attached to any network.
  • External IP of a modem is added as a separate interface of type wan with address type external. Mask, gateway, and MAC can be left blank.
  • Wi-Fi: broadcasting vs connecting. Networks the device broadcasts go into the Wi-Fi networks block. Connections to an existing network go into a wifi interface via the Connected Wi-Fi network field.
  • DHCP warning. If a static IP falls into a pool range, a yellow banner appears. This is a warning, not an error, but check for conflicts.
  • Uniqueness within a home. Hostname, Local IP, location names, and network names are unique within a home. MAC is globally unique.

14. Troubleshooting

"Safari cannot open the page". Rare. This is a Safari quirk with long pauses between opening a form and submitting. Press Back and save again — it should work.

"Internal Server Error". A server-side error. Contact the administrator.

I see no homes. Ask the administrator to assign you to at least one home.

Cannot delete a home. Only empty homes can be deleted. Remove or move all devices, locations, and networks out of it first.

Cannot delete a reference entry. Devices reference it. Remove the references first.

Forgot password. The application password can be reset by an admin via the Users section. Device passwords are stored in plain text on the device page — they can be viewed there.

IP address will not save. Check: the address is unique within the home, the gateway is in the same subnet (except for external), the MAC is filled in for dhcp and reserved, the interface is not of type port.

Connection will not save. Check: Source and Target are different ports, the connection does not already exist, both ports belong to devices of the same home, both devices have ports.
